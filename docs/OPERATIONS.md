# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 查看「组级发布包」：每个已对平的组各自成包并可下载，暂缓组列出原因。已入包的组不必等待其他组补录。
5. 对账无差异且无坏行时可整批签发。部分组暂缓时，可签发组已通过发布包交付，整批可填写暂缓意见记录剩余原因。
6. 补齐后重跑：内容未变的组继续引用原版本，内容变化的组生成下一个版本，旧签发仍可回读。
7. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
